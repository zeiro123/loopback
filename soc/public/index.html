Autonomous response policy

When an alert or the risk engine crosses a threshold, the SOC acts on its own: blocks the user and revokes their live sessions on the target. Every autonomous action is logged in Response Actions.

Overview

Live threat posture: counters, severity distribution, risk leaderboard, latest alerts and actions. Auto-refreshes every 2.5 seconds.

Live Traffic

Every REST + GraphQL request the bank processed, paired with the SQL it produced via the trace join. Filter by API, user or endpoint.

Users

Every tracked actor with client ID, IPs, devices, volume, alerts and live risk score. Click Investigate for the risk breakdown with feature contributions, the full activity log, and response actions.

Alerts

Filter by severity and attack type. Each alert carries the detailed attack path — device, session, API, SQL, tables, impact — and raw evidence. Respond inline: Block User, Revoke Session, or Dismiss.

Normal vs malicious

Signing in, checking your own balance, downloading your own statement, and sending transfers are never flagged. Detections fire only when a session crosses into data it does not own: other users' PII, statements, API keys, applications, or chatbot-mediated balances.

Response Actions

The full audit of every action — manual or autonomous — with the reason that drove it. Autonomous entries cite the thresholds met and the alert that triggered them.

Blocking

A blocked user loses all live sessions immediately, cannot sign in again, and receives HTTP 403 on every bank API call. Individually revoked sessions die instantly too.

Triggering detections

From the bank on :5000: swap account numbers on statements or API keys (IDOR), submit negative or oversized transfers (business logic), sweep several accounts fast (enumeration), or ask the chatbot about another client's balance.

1. Synthetic data only

Every account, transaction, job application and chat message in this lab is synthetic. No real personal data, no real financial institution.

2. Isolated use

The vulnerable target and the SOC are for local, isolated lab use. Do not deploy publicly and never point these tools at systems you do not own or have written authorization to test.

3. Deliberate vulnerabilities

The bank intentionally contains BOLA/IDOR, business-logic, chatbot-leak and enumeration flaws for detection research. Its credentials (Mary/peter, admin/admin) are documented lab defaults, not secrets.

4. Autonomous actions

The SOC can autonomously block users and revoke sessions according to the configured policy. In this lab those actions only affect the synthetic target.
